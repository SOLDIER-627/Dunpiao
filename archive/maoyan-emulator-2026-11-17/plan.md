# 猫眼优先：本地模拟器方案

更新：2026-11-16。用户报告猫眼 App 已能登录，决定先做猫眼，恢复本地模拟器。大麦 USB 真机方案保留作候选，旧模拟器的大麦登录失败记录仍有效。开源依据见[猫眼开源实现核查](../research/2026-11-16-maoyan-open-source-review.md)。

## 目标与验收边界

在用户自己的猫眼账号上，实现单设备、单场次、可观察且可立即停止的购票辅助。首版验收是：本地 AVD 中人工登录成功、能识别目标演出和页面状态、能按用户指定的场次/票价/张数/观演人走到订单确认页。真实提交作为后续独立验收；支付由用户本人处理。**目前只知道用户在某个环境能登录猫眼，尚未核实新本地 AVD 的登录和下单能力。**

## 设备与工具

- Apple Silicon Mac；项目内独立 Android SDK 与 AVD，不修改全局 Android 环境。
- 一台 Android 15 / API 35 / ARM64 Google Play 镜像的 Pixel 7 AVD。只恢复这一台，不恢复旧的 Google APIs 副本。Google Play 中由用户自行安装官方猫眼 App 并登录；不迁移云手机或真机的登录数据。
- 保留简体中文、屏幕底部三键导航、Mac 键盘输入设置。启动脚本使用 `Ticket_Maoyan_API35`，避免和旧归档 `Ticket_API35*` 混淆。
- PC 端 Python 负责配置、定时、状态记录、停止信号和单次运行协调；Appium/UiAutomator2 通过 ADB 读取页面可访问性树并执行有限操作。先验证页面可读，再安装自动化依赖。

官方安装依据：[Android 命令行工具](https://developer.android.com/tools/sdkmanager)、[AVD 创建](https://developer.android.com/tools/avdmanager)、[模拟器启动](https://developer.android.com/studio/run/emulator-commandline)、[UiAutomator2 驱动](https://github.com/appium/appium-uiautomator2-driver)。

## 软件结构

```text
用户配置（只存演出、时间、票档、张数、观演人别名）
             │
             ▼
协调器：预检 → 等待开售/监控 → 有限尝试 → 停止/通知
             │
             ▼
猫眼适配器：页面判态、场次/票档筛选、数量/观演人核对
             │
             ▼
Appium/UiAutomator2 → ADB → Ticket_Maoyan_API35
             │
             └── 脱敏事件日志、必要时的本地截图
```

页面状态：`未登录`、`演出详情`、`预约/待开售`、`开售入口`、`场次选择`、`票档选择`、`选座`、`观演人/数量`、`订单确认`、`待支付`、`售罄`、`排队/验证`、`网络错误`、`未知`。所有动作必须带前置状态与操作后的目标状态；超过超时、状态不符或断线就停止。验证码、排队、访问拒绝交给用户人工处理并暂停流程。

## 两个运行模式

1. **开售模式**：用户提前手动打开目标演出页并确认登录、预约/预填信息；脚本校验目标和时间，等待开售，识别页面上出现的购票入口，按配置选择场次、票档和人数，到订单确认页停下。定时器只决定何时开始观察，不依靠无界高频点击。
2. **余票模式**：用户指定场次与最高票价；在有界时间窗口内读取当前票档状态。只有明确显示可购且满足票价条件才进入后续步骤；刷新次数、最短间隔和总运行时间均可配置，达到上限就退出。

首版优先非选座场次。选座流程需单独采样座位图、锁座和不可用座位状态后再实现。不要将“进入支付页”写成“购票成功”；只有订单状态可用且用户确认时，才能标注订单已创建。

## 定位与核对规则

- 优先可访问性 ID、可见文本与控件层级；固定坐标仅在记录屏幕尺寸、截图和页面版本之后作为显式兜底，且不能用于提交/支付。
- 票价和场次必须同时匹配。选中后再次读取订单摘要，核对日期/场次、单价、数量、总价、观演人数量与用户配置；不一致直接停。
- 提交前再次检查是否已有相同目标的待支付订单，避免重复下单。真实提交默认关闭，单次运行最多一次提交动作，检测到待支付立即停止并交给用户。
- 对页面空白、价格图片化、控件树缺失的情况记录脱敏截图与失败原因；先人工复核，再决定是否加入 OCR，不把 OCR 结果单独作为提交依据。

## 阶段门槛

| 门槛 | 可观察结果 | 未通过时 |
|---|---|---|
| M0 设备恢复 | AVD 启动、`adb devices` 在线、中文/三键/键盘可用 | 修复 SDK/镜像/配置，不安装 Appium |
| M1 猫眼登录 | 用户在本地 AVD 的官方猫眼 App 人工登录并能重新打开仍保持登录 | 保留完整报错形态；停止本地模拟器路线的业务开发 |
| M2 页面可读 | 目标演出详情、场次和票档有稳定可读的状态或明确的视觉兜底 | 调整定位/人工采样，不靠盲点坐标 |
| M3 提交前流程 | 演出、场次、票档、人数、观演人及金额核对正确，未知页安全停止 | 修复适配器，禁止真实提交 |
| M4 订单实测 | 用户选择一次非热门有效场次并监督；只创建一张目标订单，支付由用户完成 | 记录失败阶段，不推断与登录闸相同 |

## 不确定性

猫眼在雷电云或其他环境能登录，不意味着本地 AVD 也能登录。登录能过不意味着下单能过。开源脚本的页面词、控件结构和触发频率可能已过时；本机样本优先于仓库默认坐标。项目不做设备指纹伪装、接口签名逆向、验证码代解、批量账号或自动支付。
