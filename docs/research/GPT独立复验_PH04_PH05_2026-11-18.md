## C1–C6 结论

| 编号 | 结果 | 独立证据与限定 |
|---|---|---|
| C1 详情 CTA 不在无障碍树 | **确认现象，成因待证** | 当场只读探针返回 `detail_page`、CTA 容器 `present=true / empty=true`、`button_ready=false`，截图中“立即预订”可见，区域均值 `[235,116,59]`。这证明当前页面的按钮视觉存在而 XML 不暴露按钮节点。交接文档归因于 `BricksChannelPageActivity`；本轮 `dumpsys window` 只检出 `ProjectDetailActivity`，因此**独立窗口/Bricks 是推论，不作为已确认根因**。 |
| C2 CTA 三种颜色 | **样本值复现；“判活”表述过强** | 用原始截图与 XML 容器 bounds 重新计算：详情亮橙 `[235,116,59]`、SKU 未选档浅橙 `[241,176,132]`、选档后亮橙 `[236,127,67]`，均与交接一致。原函数对浅橙也返回 `button_visually_rendered=true`；这只能证明视觉上有按钮，不能证明可点击。本轮新增 `appearance_hint` 与保守的 `likely_active`，浅橙返回 `false`；仍需以页面状态和后续页面变化核验。 |

## PH-05 历史证据链复核

交接文档指向的 `logs/ph05_20261118_101416/` **不是完整流程目录**：该目录只有 s1 状态误判中止。实际成功/失败记录散在多个时间戳目录：`101602` 的 s1 到 SKU 成功，`101609` 的 s2 选档后仍在 SKU 并以 `rc=1` 结束，`101633` 的 s3 日志记录一次提交点击，随后截图显示支付宝收银台。中间“确定”由后续页面样本与本轮独立现场复现支持，但不在同一个自动化 run.log 中。

因此历史证据支持“曾到达收银台”，也支持本轮的两步流程；**不支持把 `101416` 当作一条完整、单次运行且正常退出的自动化轨迹**。`101633` 日志没有结束行；既有截图可见支付页面，不能据此声称脚本正常退出。历史提交已发生，本轮没有重复提交。

## 上游原版只读基线

`reference/HaTickets/mobile/scripts/start_ticket_grabbing.sh --probe` 首次未运行到探测阶段：脚本要求上游仓库自身存在 `.venv` 或 Poetry，而本项目 `.venv` 在 Ticket 根目录。随后用已核对 `probe_only=true`、`if_commit_order=false` 的本地配置，经上游 Python 入口复跑，退出码 0；日志记录 `detail_page`、`device_ready=true`、`coord_ready=true`、`probe_only` 在购票点击前停止，耗时约 0.88 秒。该 ready 是**容器坐标级**，与 C1 的“按钮节点不可见”同时成立。原始日志保存在 `logs/gpt_reverify_upstream_direct_2026-11-18.log`。

## 本轮代码收紧与后续验证

- `src/dunpiao/probe.py`：保留“视觉存在”字段，新增亮橙/浅橙/未知外观线索及保守的 `likely_active`。三份既有截图的离线回归分别得到 `true / false / true`；颜色启发式不等于实际库存或可点击性。
- `scripts/ph05_flow.py`：s1 仅在 CTA 为已见亮橙态时点击；s2 按现场确认的“两步制”先选档再点确定；s3 总价从子串检查改为精确 Decimal 比较，观演人改为逐一匹配。**s2/s3 修改后没有再次实机执行**，下一次使用前应做订单提交前回归；本次复验不触碰 s3。
- C1 的 Bricks 归因、C3 的跨场次可选规则、C6 的登录拦截/全售罄分支，以及 PH-05 正常退出，仍需分别补证。当前样本不支持“热路径 <2 秒”的结论。
