更新：2026-11-16。本文保留早期生态调研及当时的性能、版本与热度描述；这些描述未经当前真机复核，不作为实施承诺。**2026-11-17 起的实施取舍以[多仓融合与 HaTickets 改造清单](多仓方案融合与HaTickets改造清单_2026-11-17.md)为准**：HaTickets 为主代码基线，其他仓库按模块参考。细节证据见早期调研文档对应章节。

## 一、五篇重点精读（本轮，README 级 → 代码级）

### 1. WECENG/ticket-purchase —— 第一代码参考【已精读源码】

- **7541★，活跃（2025-09 v2）**；Python + Appium/UiAutomator2，双端（Web Selenium + 安卓）
- **路线**：PC 驱动真机/AVD，与我们同栈；底层同为 UiAutomator2 引擎
- **可采纳**：
  - cn.damai 9.x 资源 ID 清单（CTA `trade_project_detail_purchase_status_bar_container_fl`、票价容器 `project_detail_perform_price_flowlayout`、`layout_num`/`img_jia`、`btn_buy_view`）——跨大版本稳定实证
  - 票价 Text 为空串（图片化）→ `price_index` 索引必选，文本匹配对票档失效
  - 提速设置：`waitForIdleTimeout=0`、坐标 clickGesture(30-50ms)、显式等待 2s、观演人坐标批点（10ms 间隔）
  - 重试纪律：2s 间隔、≤3 次、重建 driver
- **红线**：无
- 详见调研文档 §六点八

### 2. currycan/HaTickets —— u2 直连路线的最佳工程参考【已精读】

- **595★，活跃（2026-11 仍在更新）**，Apache-2.0；Python + **uiautomator2 直连**（无 Appium 中间层），与我们选型完全一致
- **官方立场（重要）**：真机为硬性门槛（模拟器易风控）；**Desktop/Tauri mtop 直调路线官方废弃**——反向确认我们"不碰接口直调"的决策
- **可采纳（DM-04 直接对标）**：
  - `clock_sync.py`：**时钟信任评估**——开售时间锚定到 `time.monotonic()`（免疫 NTP 跳变），offset 警戒 150ms / 严重 1000ms，严重时**降级为纯 CTA 轮询**；默认不连 NTP，可注入外部时间源
  - 配置 schema：`probe_only`（只探测不点击）、`auto_navigate`、`sell_start_time`(ISO)、`countdown_lead_ms=3000`、`fast_retry_count=8 @80ms`（不重建 driver，比 WECENG 更激进）、`rush_mode`（信任 price_index、跳过冗余读取、热路径 <2s）、`if_commit_order` 提交闸门
  - 模块化状态机：`state_probe` / `page_probe` / `buy_button_guard`（CTA 就绪词 vs 拦截词表）/ `recovery_strategies` / `coords_cache`（热路径坐标缓存）/ `runtime_lock`（防双跑）/ `submit_journal` / `run_report`
  - 热路径：坐标缓存 + 单次 HTTP 调用完成点击；预热 slack 1200ms / 预热警告 500ms
- **红线**：Desktop 的 baxia 凭证伪造、UA 伪装、代理支持——不采纳
- 详见调研文档 §六点九

### 3. Szymou/NNBS —— 票圈生态与时间对齐情报【路线不采用，情报已提取】

- **390★，2023-11 停更**；AutoJS 手机本机路线（进程/包名可枚举，暴露面大，弃）
- **可采纳**：
  - **大麦官方对时接口** `GET https://mtop.damai.cn/gw/mtop.common.getTimestamp/`（公开只读）——对裁判的钟
  - **0 秒抖动 500ms**：0 秒瞬间按钮翻"立即订购"→弹回"立即预约"（App 0 秒再校时），整点立刻点会点空
  - 提前量 -40ms 补偿；资源 ID 定位（8.x 时代，与 WECENG 清单互证）
  - 回流监测设计（二次回流、"我知道了"自动点、场次/周几过滤）→ P4
- **红线**：滑块模拟滑动脚本（=验证码代解）；不采用
- 详见调研文档 §六点六

### 4. Guyungy/damaihelper —— Web 控制台工程参考【骨架，非抢票能力参考】

- **4481★，活跃（2026-08）**；明言默认 dry-run、"不保证真实抢票效果"
- **可采纳（P2/P3 直接对标）**：
  - API 契约：`/api/health`、`/api/config`、`/api/ticket/start|stop`、`/api/ticket/logs?offset=`（增量日志）
  - 任务编排：阶段流、可停止、增量日志回传；`dry_run` 默认 = 我们 `commit_order=false` 同构（设计收敛佐证）

## 三、跨仓库收敛结论（设计基线）

1. **载体**：真机 > AVD > 云手机（已实测淘汰）；Appium/u2 双栈底层同为 UiAutomator2，我们选 u2 直连（无中间层）
2. **冷路径**：预配置最强形式 = 大麦"预选"（App 自己记住）+ 提前 3-7 天行为预热
3. **热路径**：CTA 轮询（200ms）→ 0 秒抖动 ~500ms → 3 步内完成（CTA/确定/提交）；对时 = NNBS 接口测 offset + HaTickets monotonic 锚定 + 提前量补偿
4. **重试**：快速重试 80ms×8（不重建 driver）或 2s×3（重建）两档；库存不足不重试
5. **安全设计收敛**：dry_run/commit 闸门、probe_only、runtime_lock、submit_journal——所有活跃项目独立收敛到同一套，作为我们默认
6. **红线一致**：滑块代解、签名逆向、接口直调（baxia/UA 伪造）、代理池——主流仓库要么不做要么已弃
