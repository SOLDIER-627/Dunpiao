## 当前现场状态

Mac 是 Apple 芯片。电脑应用清单能看到“雷电云手机”客户端正在运行（应用标识 `com.ldy.csldy.mac`），但本轮未获准读取其窗口内容，因此尚不知道客户端版本、登录状态、已有设备或试用权益；也未购买云手机。下列任何“通过”都必须在实际客户端中观察并记录。

## 一、验证顺序与停止点

| 阶段 | 动作 | 通过标准 | 未通过时 |
|---|---|---|---|
| C0 客户端 | 打开已安装的雷电云 Mac 客户端，核对版本、账号状态、是否有现成设备或免费体验；由用户本人完成登录 | 能打开一台云端 Android 设备，记录系统版本、分辨率、套餐类型和是否有试用期限 | 无设备时先核对可用试用，不默认购买长期套餐 |
| C1 App | 在云手机内从可信应用商店安装大麦，由用户本人登录一次；打开非热门演出详情 | 原生大麦 App 登录成功，详情/场次/票档可浏览 | 出现“访问被拒绝”时记录页面、时间和版本，停止重试；不把网页登录成功当作 App 通过 |
| C2 人工操作 | 测侧栏返回/主页/最近任务、Mac 键盘输入、截图、窗口缩放、断线重连；人工点 10 次普通非订单操作并记录响应时间 | 页面能稳定回显，重连后状态可核对，用户随时可接管 | 先排查客户端操作；持续不稳定则不做抢票 Demo |
| C3 自动化入口 | 查客户端及官方客服是否提供普通用户可用的 ADB/正式 API；同时确认 Mac 端宏录制是否存在 | ADB 可重复连上，或 PC 客户端窗口可稳定截图与点击 | 不假定“支持宏”就等于支持 Appium；无可靠控制/观测则只做人工试用 |
| C4 只读 Demo | 页面识别、定时等待、状态记录与停止，点击到购票入口前 | 连续 3 次能正确识别关键状态；未知/掉线不继续点击 | 修复识别或回退人工操作 |
| C5 提交前 Demo | 在非热门场次走选场次/票档/观演人，停在提交订单前 | 能显示目标、票价、张数和观演人供用户核对；没有真实订单 | 记录具体失效页面，禁止自动提交 |

C1 是首个决定性关口。此前他人的订单照片只证明使用雷电云 PC 界面，**没有**证明该账号能在云端登录，也没有证明订单由脚本创建。登录通过之后，仍需单独验证实际下单阶段是否被平台拒绝。

## 二、两种实现路径

### A. 官方 ADB / 正式接口（优先确认）

若雷电云明确提供普通账号可用的连接方式，先用只读命令验证 `adb devices -l`、截图、前台包名和 UI 层级。然后复用已有的 `DeviceAdapter`、UiAutomator2 页面状态机设计。连接地址、授权方式、超时和多设备标识均以官方文档及本账号实测为准。**本轮尚无这项证据，不预先写或安装连接器。**

### B. Mac 客户端窗口视觉控制（ADB 不可用时）

在用户允许控制客户端后，以固定窗口大小采集画面，按“截图 → OCR/模板识别 → 页面校验 → 单次点击 → 再截图”的闭环工作。定位基于云手机**内容区域**，排除侧栏和客户端窗口装饰；记录窗口尺寸、缩放和云手机分辨率，不用未经校准的绝对屏幕坐标。视觉识别优先明确文字与按钮样式，票价图片化时用 OCR；对低置信度状态直接停止。调度器只负责时间、最大尝试次数和停止信号，执行器每次动作前确认前台窗口和目标页面。掉线、登录失效、验证码、人脸、访问拒绝或订单摘要不一致立即交还用户。

这一方案会受视频流延迟、窗口遮挡和画质影响；要先通过 C2 的稳定性试验。Mac 客户端若没有可靠的截图/点击能力，不应靠盲点坐标实现订单流程。系统需要屏幕录制或辅助功能权限时，由用户审阅并操作授权。

### C. 客户端宏录制（仅固定步骤演示）

官方文档确认 PC 端有宏录制与回放，但尚未确认已安装的 **Mac 版**提供相同功能。宏只适合重复、固定、无歧义的低风险步骤，例如打开应用或进入已知页面；不负责判断售罄、票档变更、实名信息或订单提交。宏若可用，也需人工监控并设明确停止点。

## 三、Demo 的最小结构

```text
本地配置（演出/场次/票档，不存登录凭据）
  → 调度器（开始时间、超时、停止、有限重试）
  → 状态识别（截图/可选 UI 层级）
  → 动作执行（官方 ADB 或 Mac 窗口）
  → 结果核对（每一步后重读画面）
  → 提交前摘要 / 人工接管
```

首版只允许一个云手机设备、一个用户账号。状态至少包括：设备离线、App 未登录、演出详情、待开售、可购、选票档、订单确认、提交前、支付页、售罄、访问拒绝、未知。默认 `commit_order=false`；支付由用户完成。结果日志只记录脱敏状态与时间，截图放在忽略 Git 的 `pagesamples/` 中，分享前遮住手机号、姓名、证件及订单号。

## 四、需要实际记录的台账

一次试用填写：客户端版本、云手机套餐/Android 版本、云手机分辨率、大麦安装渠道和版本、首次登录结果与精确报错、详情/票档可用性、侧栏三键和键盘、平均与最慢响应、断线重连表现、ADB/宏是否有官方支持、最终是否进入 C4。每次尝试仅在状态有信息增量时重做；遇拒绝访问不高频重复登录。

## 五、当前行动与预算边界

1. 先使用已安装客户端和现有账号/免费体验；不购买长期套餐。若页面只有付费设备，记录可选最短体验、Android 版本及费用，再决定是否试购。
2. 用户本人完成云客户端和大麦账号的登录、短信或人脸验证；不在聊天、脚本或仓库中传递密码和验证码。
3. C1 通过后才投入 C2/C3；C3 有结果后选 A 或 B，先交付只读 Demo。若 C1 失败，结束雷电云路线并恢复实体真机方案。
4. 本方案不使用 root 隐藏、机型/指纹伪装、验证码代解、签名逆向或自动支付。

## 资料来源与证据边界

- [雷电云官网](https://www.ldyuncs.com/)有 Apple 芯片 Mac 客户端入口。
- [官方 PC 界面说明](https://www.ldyuncs.com/course/104532)列出三键、安装、截图、剪切板等功能；是否与 Mac 版完全相同待实测。
- [官方 PC 宏录制指南](https://www.ldyuncs.com/course/107288)说明录制与回放；没有承诺页面状态识别。
- [官方常见问题](https://www.ldyuncs.com/course/100760)提示云手机有网络操作延迟，且设备存在 root 能力；这使大麦 App 登录的实际试验尤其重要。不要通过修改机型或隐藏 root 代替可行性验证。
- [WECENG 真机 issue](https://github.com/WECENG/ticket-purchase/issues/14)与 [HaTickets README](https://github.com/currycan/HaTickets)支持实体真机路线，但不能据此断言雷电云必定失败。
