| `d(text=…).count` | 35~178ms（中位 48ms） | |

## 3. 三轮提速都改了什么

### round1（上游等待策略移植）
- `wait_for_page_state` deadline 轮询 poll=0.2、就绪检查 0.05、`wait_timeout=0`+`operation_delay=(0,0)`；像素验证只在决策点做。8.6 → 5.3s。

### round2（用户手动实测驱动，5.58 → 4.75s）
- 票档稳定性 3 轮 → 2 轮（防误选缺货档的保底不变）

### round3（快查询轮询，4.75 → 4.00s）——照上游 rush_mode 哲学
- **页面转换全部改 u2 选择器快查询轮询**（~50ms/轮），dump 只留在必须读文本的决策点：
  - CTA 点击后：`project_detail_perform_price_flowlayout` 存在性轮询确认进 SKU（已核验该 ID 在详情页 0 处出现，仅 SKU 页有——快查询无歧义）
  - 票档稳定：`d(text="缺货登记").count` 计数在 **≥0.8s 窗口不变且 SKU 驻留 ≥1.2s** 才认定标签已定，然后单次 dump 拿 bounds+护栏（替代原 2 轮 dump 签名稳定）
  - 确定按钮：**仅截图像素轮询**（bounds 来自上一次 dump），0.98s → 0.24s
  - 订单页：`cn.damai:id/checkbox` 存在性轮询（上游 `_wait_for_submit_ready` 同款 ID）→ 单次 dump 做全字段核对
- 新增 `Runner.fast_poll()`（u2 快查询轮询，异常重试 + 有界超时）

## 4. 剩余 4.0s 的构成（地板分析）

| 段 | 耗时 | 归属 |
|---|---|---|
| CTA → SKU 容器 | 0.4s | 大麦渲染，不可压 |
| SKU → 缺货标记稳定 | 1.9s | **大麦标签异步渲染 ~1.1s + 0.8s 稳定窗口**（防误选的安全代价） |
| 选档 → 确定亮橙 | 0.2s | 我们，已到底 |
| 确定 → 订单标记 | 0.8s | 大麦渲染 0.5s + 我们 dump 0.3s |
| 订单 → 核对完成 | 0.6s | dump + 核对 |

- 我们的可压成本仅剩 ~1.2s（两次 dump 是核对/定位的必需证据）
- **大麦自身渲染 ~2.1s 是物理地板**
- 再砍只能动闸门（跳过标签稳定窗口直接点=回到误选缺货档的坑），**建议不动**

## 6. 0 秒抖动与我们的对策（待 P3 真实开票验证）

调研记录（WECENG/NNBS 实测）：大麦 0 秒瞬间按钮翻"立即订购"→弹回"立即预约"约 **500ms**，整点立刻点会点空。
我们的 wait-open 已内置对策：T0 直点若未进 SKU（快查询 3s 内票价容器未出现），**自动回落到亮橙闸门轮询路径**继续点击——相当于自带抖动重试。P3 场次要实测这个窗口实际多长。

## 7. E2E-07 顺带修复的三个时间轴坑（复验时注意）

1. `strptime("%H:%M")` 默认年份 1900 → 目标掉到过去、**提前 69 秒点击**（闸门拦住）
2. **anchor 采样点被 sntp 耗时拉开 1~3s** → deadline 整体晚 1.77s（最隐蔽；受控实验定位：20s hold 偏差仅 4ms，排除 sleep 粒度）——修法：anchor 两采样紧邻且在 `sample_clock()` 之后
3. sleep 过冲累积 → hold 循环 0.05s 粒度

sntp 为本地扩展（Apple 自家 NTP `time.apple.com`；上游 systemsetup 需管理员权限在本机永远 unknown——上游 macOS 路径的盲区，上游 docstring 明确支持注入测量值）。
