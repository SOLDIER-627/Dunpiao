# 大麦优先的代抢脚本实现方案

> **历史方案：**本地模拟器路线已终止；当前架构见 [HaTickets 真机接入方案](HaTickets真机接入方案_2026-11-17.md)。以下内容不再作为实施任务。

**日期：**2026-11-16　**目标：**真实 App 页面上的单账号购票辅助，而非反制仿真。

## 技术路线

采用 Python 作为调度器，通过 Appium/UiAutomator2 操作安卓模拟器中的大麦 App。用户自行在 App 内登录和维护观演人；脚本只读取页面可见状态，按事先确认的场次、票档和人数操作。到支付页后停下并通知用户。猫眼作为第二个页面适配器接入同一调度器。

选择这条路线的依据：公开仓库 [yanzilee/damaiTickets](https://github.com/yanzilee/damaiTickets) 主推 Android 移动端并将其 Desktop 路线标记为不可用；[LiLeo505/ticket-puchase](https://github.com/LiLeo505/ticket-puchase) 亦集中于 Appium/UiAutomator2；猫眼仓库 [Pactum7/ticket-grabbing](https://github.com/Pactum7/ticket-grabbing) 展示了移动端卡点和余票监控思路。这些是架构参考，不能替代本机兼容性测试。

## 模块划分

```text
启动命令 / 本地配置
        │
        ▼
运行协调器 ── 定时等待、停止信号、尝试次数、超时
        │
        ▼
平台适配器 ── 大麦（首版） / 猫眼（后续）
        │
        ▼
页面驱动 ── Appium/UiAutomator2 ── 安卓模拟器中的 App
        │
        └── 运行日志、截图、状态提示
```

平台适配器只承担页面识别和页面操作；协调器不写入平台专属页面文本。页面状态以 `未登录 / 演出详情 / 票档 / 确认 / 支付 / 售罄 / 未知` 表示。每一步先确认页面与预期相符，再执行操作；无法确认时停止并留下诊断截图。

## 单次运行流程

1. 读取本地配置：演出、场次、票档、张数、观演人姓名、开售时间、最大尝试次数。进行格式与人数一致性检查。
2. 连接模拟器，检查 App 已登录、目标演出可定位、页面状态正确。准备阶段不提交订单。
3. 等待开售时刻；根据 App 页面状态进入票档选择。允许用户随时停止。
4. 逐项核对场次、票档、数量、观演人；任一项不匹配则停止。
5. 尝试提交一次；若明确售罄或暂不可购，在设定次数与时间内有限重试。检测已有订单则立即终止重试。
6. 到达支付页后通知用户并停下。日志记录步骤、耗时和原因，但不保存完整个人身份信息。

## 配置与数据保护

仓库内只放示例配置。真实配置放在被 Git 忽略的本地文件，优先用 App 内已有观演人姓名进行匹配。密码、验证码、身份证号和支付资料不进入配置或日志。运行截图可能含个人信息，默认存本机且不自动上传。

## 风险与验收重点

- **模拟器兼容：**当前机器未发现 Android Studio 或 adb。先完成环境检查，确认大麦 App 能在模拟器中登录与浏览；否则换安卓真机，不在模拟器上投入页面适配。
- **页面变化：**票务 App 页面经常变化。定位策略应优先使用可访问性元素与可见文本，并为未知页面设计停止路径。
- **重复下单：**订单状态是重试前的必检项；已有有效订单时立即结束。
- **真实表现：**公开项目 README 中的速度与成功率并非本项目目标值。验收以可重复走通流程、正确停止和日志可诊断为准。

## 不纳入首版

多账号批量抢票、验证码代解、真实平台请求逆向、风控规避、自动支付、代管他人账号。后续如需扩展，应基于实际使用场景重新评估范围。
