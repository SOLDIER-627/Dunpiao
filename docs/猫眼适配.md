# 猫眼适配

猫眼（`com.sankuai.movie`）与大麦是两套完全不同的页面实现。当前状态：

| 能力 | 大麦 | 猫眼 |
|---|---|---|
| 只读信息提取（`show_info.py`） | ✅ | ✅ 已适配（`src/dunpiao/maoyan.py`） |
| 场次 / 票档序号提取 | ✅ | ✅ |
| 抢票执行链路（CTA→确定→提交） | ✅ | ⛔ **未接入**（`engine.py` 按大麦资源 ID 编写） |
| 回流监听（`reflow.py`） | ✅ | ⛔ 未接入 |

## 实测结构差异（2026-11-18，猫眼 + 荔枝超级演唱会上海站）

| 项 | 大麦 | 猫眼 |
|---|---|---|
| 包名 | `cn.damai` | `com.sankuai.movie` |
| Activity | 详情 / SKU / 订单 各自独立 | **全在 `MRNMovieActivity`**（美团 RN 单页 + 弹层） |
| 内容 resource-id | 丰富（`btn_buy_view`、`project_detail_perform_price_flowlayout`…） | **几乎没有**（RN 自绘，只有系统栏有 id） |
| 票档卡定位 | 资源 ID + 子节点结构 | **¥价格文本 → 最近可点击祖先** |
| 场次卡定位 | `sku_panel_dates` + `tv_date` | **日期+周X 文本 → 最近可点击祖先** |
| 文案排版 | 连续文本 | 常带字间距（`已 预 约`）→ 匹配前需去空白 |
| 预约态 | 底部「预约想看场次/票档」 | 底部「已预约 · **开抢后有票会自动为您勾选**」 |

## 提取用法

```bash
# 手机停在猫眼演出详情页（或已点开的场次/票档面板）
.venv/bin/python scripts/show_info.py --serial <serial> --save-xml /tmp/maoyan.xml
```

## 状态词表

- **不可购**：缺货登记 / 已售罄 / 售罄 / 无票 / 暂时无票 / 不可选 / 暂不可售
- **预约态**：可预约 / 已预约 / 预约 / 即将开抢 / 待开售 / 开抢提醒
- **CTA 可点**：立即购票 / 立即购买 / 特惠购票 / 选座购买 / 立即预订
- **CTA 阻断**：已预约 / 预约 / 即将开抢 / 待开售 / 开抢提醒 / 缺货登记 / 已售罄

## 接入执行链路还缺什么

猫眼要跑抢票/回流，`engine.py` 需要一层平台抽象（当前写死大麦）：

1. **CTA 定位**：猫眼靠底部区域 + 文案，不是资源 ID
2. **票档/场次点击**：用「最近可点击祖先」坐标（`maoyan.extract_tiers/sessions` 已给 bounds）
3. **确认按钮**：猫眼开售后底部按钮文案待实测（可能是「立即购买」/「确定」）
4. **订单页识别**：猫眼的订单页 Activity 与页面标记未采样
5. **回流刷新**：猫眼是否也「不自动刷新库存」待实测

这些都**必须在开售后**用真实页面采样，不能靠预约态推断（大麦的教训：预约态与开售后面板布局/文案不同）。

## 猫眼的一个潜在优势

预约态底部写明「**开抢后有票会自动为您勾选**」——若开售后确实如此，猫眼链路可能比大麦更短
（不需要选档，只需确认→提交）。这一点 12.5 开售后实测确认。

## 红线（与大盘一致）

只读提取、不点确定、不提交、不碰支付；验证码/风控弹窗出现即停交人工。
