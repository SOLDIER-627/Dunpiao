# 猫眼适配

猫眼（`com.sankuai.movie`）与大麦是两套完全不同的页面实现。当前状态：

| 能力 | 大麦 | 猫眼 |
|---|---|---|
| 只读信息提取（`show_info.py`） | ✅ | ✅ 已适配（`src/dunpiao/maoyan.py`） |
| 场次 / 票档序号提取 | ✅ | ✅ |
| 抢票链路（CTA→确定→提交） | ✅ | 🟡 同一入口 `rush.py --platform auto`，前两步（CTA→选档）已跑通；确认/提交待开售实测 |
| 回流监听（`reflow.py`） | ✅ | ⛔ 未接入 |

**用法（一个入口，平台自动判断）**

```bash
# 手机停在猫眼详情页即可，平台按前台包名自动分流
.venv/bin/python scripts/rush.py --price 288 --expected-total 288.00 \
    --show-tag maoyan_lizhi_288_20261205

# 预约态模拟演练（CTA 是「已预约」也点，不提交）
.venv/bin/python scripts/rush.py --price 288 --simulate
```

## 实测结构差异（2026-11-18，猫眼 + 荔枝超级演唱会上海站）

| 项 | 大麦 | 猫眼 |
|---|---|---|
| 包名 | `cn.damai` | `com.sankuai.movie` |
| Activity | 详情 / SKU / 订单 各自独立 | **全在 `MRNMovieActivity`**（美团 RN 单页 + 弹层） |
| 内容 resource-id | 丰富（`btn_buy_view`、`project_detail_perform_price_flowlayout`…） | **几乎没有**（RN 自绘，只有系统栏有 id） |
| 票档卡定位 | 资源 ID + 子节点结构 | **¥价格文本 → 最近可点击祖先** |
| 场次卡定位 | `sku_panel_dates` + `tv_date` | **日期+周X 文本 → 最近可点击祖先** |
| 文案排版 | 连续文本 | 常带字间距（`已 预 约`）→ 匹配前需去空白 |
| 预约态 | 底部「预约想看场次/票档」 | 底部「已预约 · **开抢后有票会自动为您勾选**」 |

- **不可购**：缺货登记 / 已售罄 / 售罄 / 无票 / 暂时无票 / 不可选 / 暂不可售
- **预约态**：可预约 / 已预约 / 预约 / 即将开抢 / 待开售 / 开抢提醒
- **CTA 可点**：立即购票 / 立即购买 / 特惠购票 / 选座购买 / 立即预订

## 链路实现（同一套纪律，只换定位）

`rush.py` 检测到猫眼前台 → 交给 `src/dunpiao/maoyan_flow.py`，阶段与大麦 `engine.py` 一致：

```
s0 回详情页    activity + state 判定，不在则 BACK
s1 点 CTA      底部区域文案定位；预约/未开售文案默认拒点（--simulate 才点）
s2 面板就绪    轮询直到票档卡出现（可点击祖先 + ¥价格）
s3 选档        --price 文本匹配 > price_index 序号 → shell tap
s4 确认按钮    底部区域找 确定/立即购买/下一步
s5 订单页      ¥金额核对 →（--submit）提交 → 只读
```

已实测（预约态模拟）：s0→s1→s2→s3 全通（点开面板、选中 看台 ¥288）。

**预约态没有确认按钮**——底部只有「已预约 / 开抢后有票会自动为您勾选」，所以 s4 停在这里，
这是预期行为，不是失败。

## 开售后还需实测（不能靠预约态推断）

1. 确认按钮真实文案（确定 / 立即购买 / 下一步）
2. 订单页标记与金额文本格式
3. 猫眼是否「开抢后有票会自动为您勾选」（若真，链路可省掉选档）
4. 回流刷新节奏（猫眼库存是否自动刷新）

## 猫眼的一个潜在优势

预约态底部写明「**开抢后有票会自动为您勾选**」——若开售后确实如此，猫眼链路可能比大麦更短
（不需要选档，只需确认→提交）。这一点 12.5 开售后实测确认。
